# 跨模型测试（第二轮）：GLM 5.3 + Word 文档输入

**目的**：内容不是 Markdown，而是一份普通的 Word 文档时，不是 Claude 的模型只靠这份 skill，能不能做出同样水准的 PPT。

## 设置

- Agent：pi；模型：GLM 5.3（`zai-coding-cn`，thinking high）；用 `--skill` 加载本仓库的一份快照。这个模型不能读图。
- 输入：[`content.docx`](content.docx)，一份「上半年私行客户经营总结」，**没用任何标题样式**，和很多人手写的 Word 一样：
  - 标题靠整段加粗；
  - 章节靠「一、」「（一）」编号；
  - 流程是手打的「1. 2. 3.」；
  - 表格是 Word 表格；
  - 「过去：… / 现在：…」各占一段。
- 模板：`examples/templates/finance-ruixin.pptx`。
- 任务原文：

  > 使用 xiaoma-ppt skill，把 content.docx 这份 Word 的内容套进 template.pptx 这个模板，做一份上半年经营总结 PPT，输出到 out/ 目录。全程自主完成，不要停下来问我。

## 结果

- 6 分 46 秒一次跑完，33 次工具调用，13 页。
- 它把 docx 直接交给 plan.py，读了转出来的 [`work/content.converted.md`](work/content.converted.md)，再改 deck.json。
  - 转出来的 md 和人工转换的结果逐字相同：
    - 章节、小节层级都对；
    - 4 条核心指标认成了列表；
    - 季度 AUM 认成了表格；
    - 投顾流程认成了有序列表；
    - 引号金句认成了引用。
- 版式选择：

  | 内容 | 版式 |
  |---|---|
  | 核心指标 | 大数字 |
  | 季度 AUM | 原生柱状图，高亮最新季度 |
  | 过去 / 现在 | 左右对比 |
  | 投顾流程 | 四步流程，配图标 |
  | 下半年计划 | 大数字 |
  | 结尾金句 | 金句页 |

- 数字逐个和 Word 核对过，全部一致。
- 本目录的 `out/deck.pptx` 是用它的 `deck.json`，在当前引擎上重新构建的：lint 0 个 ❌。

## 发现的问题和改动

| 问题 | 原因 | 改动 |
|---|---|---|
| 它写了一个脚本，把成品里白底上的金色序号改成深蓝，才让 lint 过关 | lint 把**模板自带的配色**（金融模板本来就是白底金色序号，对比度 2.3）也当成 ❌，模型只能改色过检，违反了「不改模板颜色」 | lint 区分开：模板原有文字保留了模板颜色时只给 ⚠️，并写明「保留不改」；排错文档写明不要为过检改色 |
| 同一检查暴露了示例本身的问题：`run_examples.sh` 一直用 `--no-render` 跑 lint，对比度检查从没真正执行过 | — | 改成带渲染跑 lint。顺带修了两处真问题：①图表说明文字在米色底上看不清（次要文字色自动加深到对比度 ≥ 3.2）；②章节页没填副标题时，模板的示例副标题（如「这一章你会学到什么」）残留 |

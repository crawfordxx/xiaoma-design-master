# 跨模型测试：pi + GLM 5.3 独立使用本 skill

**目的**：验证不是 Claude 的模型，只靠本 skill 能不能做出同标准的视频和幻灯片。

## 设置

- Agent：pi 0.85.1；模型：GLM 5.3（`zai-coding-cn`，thinking high）；用 `--skill` 加载本仓库。
- **这个模型不能读图。** 拼图自检时它没法看图片，改用「程序化区域分析」：统计画面中心前景占比、底色、强调色、字幕对比度、帧间变化。
- 任务原文（普通用户口吻，没有任何额外指导）：

  > 使用 xiaoma-studio skill……做一个讲解「沉没成本」的视频，以及一份同主题的 HTML 幻灯片。视频 45–60 秒，16:9，纯音乐 + 中英双语字幕，不要旁白；幻灯片可直接在浏览器里演讲，并导出 PDF。全程自主完成，不要停下来问我。

- 一共两次运行，约 128 次工具调用。第一次在「接下来我会渲染……」这句话之后就自己结束了，第二次用「继续，按交付清单做完」续上。

## 据此对 skill 做的改动

1. 新增 `engine/lint.mjs`：不用看图也能检查**确定性**（乱序和顺序渲染做像素比较）、**文字对比度**（按真实背景像素计算）、**文字重叠**。用它检查本例，上表前两个问题都能抓到；8 个官方例子全部通过。
2. SKILL.md：每轮自检和交付前都必须跑 `lint.mjs`；不能读图的模型以 lint 全绿为准，并在报告里写明「未目视检查」。
3. SKILL.md：新增「**事实**」规则：片子里出现的数据必须能说出处，查不到原始数字就不写具体数字。
4. SKILL.md：「交付清单全部打勾之前，不要结束回合」。
5. SKILL.md：整片渲染耗时长，要放后台或分段跑，等文件完整写完再验收。

## 结论

只靠这份 skill，一个不能读图的非 Claude 模型也能做出结构完整、节奏合格、技术指标全绿的 58 秒科普片和 9 页幻灯片。剩下的问题集中在「视觉上要看一眼才知道」的地方和事实核查上。这两块现在分别交给 `lint.mjs` 和「事实」规则兜底。

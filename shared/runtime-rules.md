# 运行时规则（runtime-rules）

> 所有生成类技能的执行时不变量：执行模式、弹性、产出交付、工作区约定、成本纪律。

---

## 执行模式

**auto（默认）**：全自动跑完管线。唯二例外——
1. 涉及付费生成前，必须先展示 draft 档结果并等用户确认，才升 final 档
2. 图片范围/风格未指定时，主动问一次（见配图规则）

**interactive**：用户说"交互模式"/"让我选"/"先看方案"时触发。在以下节点暂停等确认：选题 → 框架 → 配图方案 → 成稿。其余步骤照跑。

规则：
- 用户给了明确主题 → 跳过选题生成，直接进框架
- 用户给了现成成稿只要排版/发布 → 跳过全部创作步骤，走最小检查
- 不要为制造交互而交互；auto 模式的价值是快

---

## 弹性规则（永不整体中断）

每一步都必须有降级路径。步骤 + 降级双双失败 → 跳过该步、在产出里记录、继续。

| 场景 | 降级 |
|---|---|
| 联网搜索失败 | 用已有素材/知识库继续，标注"未联网核验" |
| 知识库不可用 | 空 knowledge_context 继续 |
| 图片生成失败 | 输出完整提示词包，用户可自行去任何工具生成 |
| 视频生成失败 | 交付分镜表 + 提示词包（这本身就是可交付物） |
| 下载媒体失败 | 保留原始 URL，绝不重新生成（防重复扣费） |
| 历史记录写入失败 | 警告，不阻塞 |

**铁律：一次单步失败永远不值得杀掉整条管线。**

---

## 产出交付规则

每次交付（草稿/生成/列表）结尾必须有**结果链接区**：

- 本地产出文件路径（Markdown 链接格式）
- 生成媒体的本地路径 + meta 元数据位置
- 下一步建议（1 条，不要 5 条）

部分成功时：逐步列出状态（✅/⚠️/❌），说明哪些要人工补。

---

## 工作区约定

```
workspace/
├── boards/            # 素材：链接、摘录、想法（一个主题一个 md）
├── projects/<slug>/   # 一次创作的家
│   ├── brief.md       # 需求与选题理由
│   ├── outline.md     # 大纲/分镜
│   ├── draft-v1.md    # 初稿（永远保留，不改写历史版本）
│   ├── final.md       # 定稿
│   ├── images/        # 本项目图片
│   └── videos/        # 本项目视频
├── output/            # toolkit/gen 的统一产出（跨项目共享池）
└── history.jsonl      # 生成历史（自动 append，选题去重数据源）
```

规则：
- slug 用 kebab-case（`my-article` 不用 `我的文章`）
- 修改永远在新文件上（draft-v2.md），不覆盖旧版本
- 选题时查 history.jsonl 近 7 天记录去重

## 配图规则（所有技能通用）

生成图片前必须确认两件事（AskUserQuestion 或一句话）：

1. **图片范围**：封面+内文 / 仅封面 / 仅内文 / 不要图
2. **风格方向**：跟随内容调性（默认）/ 具体指定（插画风/电影感/极简/科技/暖调编辑）

用户没提但也没说不要 → 默认问一次。**绝不因为用户没提就默认"不要图"，也绝不不问就批量生成。**

## 成本纪律

1. **两档制**：`--tier draft`（低价快速，试参数试构图）→ 用户确认 → `--tier final`（正式产出）
2. **final 前查余额**（provider 支持时；executor 自动执行）
3. **超时绝不自动重发**（中转计费按次，重发=双倍扣费）
4. **批量生成前报预估**："3 张 × 约 0.2 元/张 ≈ 0.6 元，继续？"
5. 每次生成的 meta 自动落盘（可审计花了什么）

---

## 版本与引用

- 技能目录内放相对 symlink `shared -> ../../shared`、`toolkit -> ../../toolkit`，正文只写 `shared/xxx.md`；SKILL.md 里不许出现 `../`（技能以 symlink 安装，`../` 会被规整到 Agent 技能目录之外而失效，smoke 会拦）
- 生成调用只写 `$S/toolkit/gen <cap> --tier <档>`（`S`=本技能目录），绝不出现模型名
- 每个技能自己的 Gotchas（命名反模式）放在 SKILL.md 末尾，发现新坑随时补

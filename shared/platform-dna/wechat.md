# 平台 DNA：微信公众号（platform-dna/wechat）

> 三层证据模型：**平台硬约束**（官方规则）/ **可观察规范**（大量账号的实际行为模式）/ **运营默认值**（本套件的实操选择）。写作时不得把二三层当成官方规则陈述。

---

## 平台硬约束

- **外链受限**：正文中不能插外部链接；导流一律走"阅读原文"
- **原创声明**：只有真实原创可声明；转载不规范会被取消
- **标题禁令**：不得模仿官方通知口吻、不得夸张恐吓式标题
- **发布后编辑受限**：只能改少量字数；**以"发布后改不了"的心态发布**
- **视频号嵌入/话题/合集/底部组件**：随账号和灰度变化，用前先确认自己的账号有没有

## 可观察规范（头部账号的一致行为）

- 标题清晰 > 标题机灵；扫一眼知道给谁的、有什么用
- 首屏必须快速兑现点进来的理由（前 120–200 字是真战场）
- 移动节奏 > 桌面式铺陈：短段落、小标题、图打断
- 专业号像**栏目系统**而不是随机文章流
- 结尾交给读者**一个**下一步动作，不是五个

## 运营默认值（本套件的选择）

| 项 | 默认 |
|---|---|
| H1 | 即发布标题——标题质量是发布问题不是美化问题 |
| 标题结构 | 主体 + 收益放前半句（手机会截断、社交转发只显示前半） |
| 摘要 | ≤54 汉字，不重复标题，多给一个点开的理由 |
| 段落 | 手机上 2–4 行/段 |
| 小标题 | 每 3–5 段一个 |
| 配图 | 每 300–500 字一张（按 visual-prompts 决策表取舍） |
| 字数 | 1500–2500（完读率最优 1500–2000） |
| 代码块 | 渲染差，超过 5 行用截图 |
| 转化 | 每篇只设一个主要目标（关注/下一篇/加群/小程序） |

## 反模式

- 伪精确地复述推荐权重/流量池数字（没有公开依据）
- 套用无证据边界的"爆文模板"
- 标题制造好奇但正文兑现不了
- 结尾多 CTA 齐发（要所有=得到没有）
- 假设所有账号都有全部原生功能

# xiaoma-designer

## Overview

视觉是一种语言：设计 = 编码，观看 = 解码，好作品 = 把信息低噪音地送达人的认知。
任何视觉作品都要过三层关，缺一层就掉一档：

| 层 | 回答的问题 | 不过关的样子 |
|---|---|---|
| 1. 策略 Strategy | 说什么？对谁说？凭什么在乎？ | 画面精美，但不知道想干什么 |
| 2. 规范 Craft | 怎么用视觉元素说清楚？ | 有想法，但画面混乱、廉价 |
| 3. 表现 Style | 凭什么被记住？ | 正确、工整，但毫无记忆点 |

成熟度阶梯：**L1 不跑题（及格）→ L2 有规范（良好）→ L3 有表现（优秀）**。
永远按 L1→L2→L3 顺序推进，跳层 = 返工。

## 工作流 A：创建视觉作品

按顺序执行，每步决策写入对用户可见的设计说明：

1. **策略推演** → 读 `references/strategy.md`
   - 受众三问：你是干嘛的（功能）？跟我有什么关系（相关）？我为什么要用（身份）？
   - 选诉求：逻辑 Logos / 共情 Pathos / 信誉 Ethos，一主一副
   - 马斯洛层级定位 + 一个故事钩子（一句话文案）
   - 产出：基调关键词（3-5 个形容词）+ 核心信息 + 差异化动作
2. **规范决策** → 读 `references/design-rules.md`，五元素逐个做决策：
   色彩（≤5 色板 + 对比度）｜形状（圆角/曲率语言）｜字体（层级 + 正文标准化标题风格化）｜版面（第一落点 + 阅读顺序 + 接近律 + 对比比例）｜风格（全局统一）
3. **风格选择** → 读 `references/style-dictionary.md`，按基调关键词从风格词典选 1 个主流派 + 媒介质感，给出理由
4. **产出**：
   - 结构化图像生成提示词（主体 + 场景 + 风格 + 光线 + 氛围 + 逐字写出的文字内容）。
     本 skill 不绑定任何生图服务：提示词交给用户已接入的任何图像生成能力即可
   - 需要精确版式时，另出 HTML/CSS 或 SVG 排版稿
5. **自审** → 按 `references/review-rubric.md` 打分，≥L2 才交付；附 1-2 条迭代方向

## 工作流 B：评审现有设计

1. 看图先答：主题是什么？想让我干什么？（答不出 = 策略层先扣分）
2. 过五元素检查清单（design-rules.md 末尾）
3. 按评分表打分（review-rubric.md），输出：总分 + 分层诊断 + 按性价比排序的改进清单

## Quick Reference

- 文案放不下 → 砍文案，不是缩字号（K.I.S.S.）
- 画面"说不出哪不对" → 九成是对比不够，或接近律被破坏
- 想要高级感 → 先限色板（≤5 色），再选一个流派风格
- 想避开 AI 味 → 明确流派 + 媒介质感词（丝网颗粒/纸纹/笔触），禁"高清唯美梦幻大气"
- 中文生图文字必须逐字写进提示词并要求零错字，出图后逐字校对
- 同类题材都往东，你往西（差异化先于美化）

## Common Mistakes

| 错误 | 后果 |
|---|---|
| 拿到需求直接写提示词 | L1 都不过：主题漂移、元素堆砌 |
| 色彩超过 5 种 | 画面廉价 |
| 正文用装饰字体 | 可读性崩坏（正文标准化，标题才风格化） |
| 风格词只写"精美/高级/大气" | 模型只能给你平均脸 |
| 生成一次就交付 | 错字、对比度问题直接漏给用户（必须过评审） |
| 插画比 UI 按钮还抢眼 | 界面内插画喧宾夺主 |

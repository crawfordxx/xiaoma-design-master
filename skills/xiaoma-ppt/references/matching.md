# 内容怎么匹配模板

匹配分两层：**md 的结构 → 模板的哪一页**，**内容的形态 → 哪种版式**。`plan.py` 按下面的规则出草稿，模型在草稿上改。

## 1. 模板页的角色（inspect_template.py 怎么判断）

| 角色 | 判断依据 | 用来放 |
|---|---|---|
| cover 封面 | 第 1 页 | 文档标题（`#`）、副标题、日期 |
| toc 目录 | 有「目录 / CONTENTS / AGENDA」字样，或前 3 页里出现 ≥3 个序号 | 章节列表（≥3 个章节时才放） |
| section 章节 | 有大序号（01、PART 1）或大字号短标题，字少 | 每个 `##` 章节的开头 |
| content 内容 | 顶部有标题，下面有大片空白 | 每个 `###`，或 `##` 下的一段内容 |
| ending 结尾 | 最后一页，或有「谢谢 / THANK YOU / Q&A」，或是免责声明封底 | 结尾，默认保留模板原文 |
| quote 金句 | 有单独的大引号，或最大的字以引号开头 | md 里的引用（`>`） |
| hidden 隐藏 | 模板里设成隐藏的页（常是使用说明） | 不用；第一张没隐藏的页才是封面 |

同一角色有多页时：
- 内容页有**浅色和深色**两种 → 浅色放数据和列表，深色放金句和观点（`quote`、`statement`）。
- 章节页有多页 → 轮流用，保持节奏。
- 模板没有目录页或章节页 → 跳过，不硬造。
- 有两张以上目录页、其中有的高亮了某一项 → 那几张是**议程式章节页**（咨询报告常见）：每章开头放整张议程，高亮当前章。
- 有带序号的章节页时，没序号、标题在左半边的「章节页」其实是**左标题、右内容**的内容页。
- 内容页的 area 比最大的那张小 25% 以上（带侧栏、带样机图）→ 不参与自动轮换。
- 深色内容页比浅色多（发布会风格）→ 内容默认用深色页。
- 内容页带**进度标签 / 章节导航条**（边上一排或一列 ≥3 个等大短标签，当前项加粗、变色或垫底色）→ 所有内容页都用带标签的那几页，保证每页导航一致；标签写章节名，当前章用模板的高亮样子，高亮标记跟着移。
- 页脚、页码、日期占位符和带页码域的文本框由模板维护，不当槽位。

**槽位**是模板里可以填字的文本框，用 `#形状id` 引用。`title`、`subtitle`、`number`、`meta`、`items` 已经按字号和位置自动认好，deck.json 里直接写这些键就行。在 ≥3 页上重复出现的文字（品牌名、页脚）会被识别为品牌，不当作槽位，原样保留。

**内容安全区 area**：标题下方、页脚上方，再避开 logo、装饰和背景图里的插画（吉祥物、山水、齿轮），剩下的最大矩形。背景里的插画是渲染后按像素找出来的：细线和网格不算占用，大块图形和文字才算。

## 2. md 结构 → 页

内容是 txt / Word / PDF 时，先由 `convert.py` 转成 md（Word 的「标题」→ `#`、「标题 1」→ `##`、「标题 2」→ `###`；没用样式时「第一章 / 一、」→ `##`，「（一）/ 1.1 / 单独一行的短句」→ `###`），再按下表走。

| md | 生成 |
|---|---|
| `# 标题` | 封面标题。标题里有「——」时，后半句做副标题 |
| `#` 下面的引用、短段落 | 封面副标题；带日期的放进 `meta` 槽 |
| `## 一、开场：xxx` | 章节页。自动去掉「一、」「第一章」这类编号（编号由模板的序号位给出）；「开场：」「附录：」这类前缀变成副标题 |
| `### xxx` | 一页内容，标题就是 xxx |
| `##` 下面没有 `###` | 按「铺垫段落 → 主体（列表/表格/引用/图） → 紧跟的加粗结论」切成若干页 |
| 「附」「附录」开头的章节 | 不进目录 |

## 3. 内容形态 → 版式

按顺序判断，先命中先用：

| 内容形态 | 版式 | 例子 |
|---|---|---|
| 两段列表，各自前面有一个短标签（过去/现在、传统/我们） | `compare` 左右对比，后面一句短话做结论条 | 「**以往** …… **现在** ……」 |
| 列表每项以时间、年份、阶段开头 | `timeline` 时间线 | 「2026年3月：……」「第一天上午：……」 |
| ≤4 项、每项都有关键数字 | `stats` 大数字（数字前的词做标签，后面的话做说明） | 「管理规模 **1,286 亿元**，同比增长 18.6%」 |
| 有序列表（1. 2. 3.），2–6 项 | `process` 流程 | 「1. **拆解岗位**：……」 |
| 2–6 项「小标题：说明」 | `cards` 卡片；一半以上能对上图标就配图标 | 「**获客成本上升**：……」 |
| 其他列表 | `bullets` 要点 | |
| 表格有数字列 | 原生图表：时间序列（年/月/季度）≥6 个点用折线，否则柱状；占比（列名带占比/比例，或百分比合计≈100）用环形；类目名长或 >7 个用横条 | |
| 表格两列数字量级差 >8 倍 | 两张图并排（`split`） | 客户数 vs 户均资产 |
| 表格没有数字、说明很长 | 卡片，按说明长度每页 2–4 张 | 平台 / 定位 / 详解 |
| 其他表格 | `table` | |
| 引用 `>` | `quote` 金句页（优先用深色内容页） | |
| 段落里有加粗金句、总字数 ≤160 | `statement` 观点页 | |
| 只有一两句话 | `statement` | |
| 纯段落 | `text` 正文页（草稿会提示「建议精简」） | |
| 图片 `![](...)` | `image` 图文页 | |

附加元素：
- 主体前面最后一个短段落（≤64 字，加粗优先）→ `lead`，页面顶部的一句话结论。
- 主体后面紧跟的加粗句 → `conclusion`，页面底部的结论条；大数字页里则变成数字下方的 `note`。
- 这个单元的所有原文 → `notes` 演讲者备注。

## 4. 模型在草稿上该改什么

草稿是规则的产物，规则不懂内容。逐页检查：

1. **版式和意图对不对**：草稿把「三个问题」做成了卡片，但你想强调的是其中一个数字 → 改成 `stats` 或给卡片加 `value`。
2. **一页是不是只有一个重点**：一页里既有 `lead` 又有 `conclusion` 又有 6 张卡 → 拆页或删掉一个。
3. **字数**：卡片说明超过 40 字、要点超过 30 字 → 从原文里删（保留主干），完整句子留在 `notes`。
4. **图表要不要强调某一项**：`highlight` 标出要讲的那根柱子；有一句关键结论就加 `takeaway`。
5. **图标对不对**：图标只是辅助识别，对不上就删掉 `icon`，不要硬配。可用图标见 `engine/icons/`。

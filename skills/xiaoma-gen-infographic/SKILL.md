# 知识信息图（gen-infographic）

把知识变成一张"看一眼就懂"的图。布局有框架，文案有结构，提示词可复用。

## Onboarding

> ✅ **知识信息图生产线已就绪！**
> 给我一个主题（"护发""血糖管理"）或贴一段素材。
> 我会先出信息架构方案（几个模块、什么布局、每块写什么），确认后生成。

## Usage

- "做一张关于护发的信息图" —— 从主题开始（会先调研补全知识）
- 贴一段文字 + "图解这个" —— 从素材开始（提炼不添加）
- "对比式布局" —— 指定布局

## Pipeline

下文 `S=<本技能目录>`（直接用安装路径，不必解 symlink）；`$S/toolkit/gen` 是生成能力的唯一入口。

**Step 1 知识模块拆解**：主题模式下先联网/知识库调研，拆出 4–6 个知识模块（多了塞不下，少了显空洞）。素材模式下只提炼不添加。每模块 = 小标题（≤8 字）+ 一句核心信息 + 支撑细节。

**Step 2 布局框架选择**：按内容逻辑选五大布局之一：
- **阶梯式**（递进/流程）：步骤类知识
- **对比式**（左右分屏）：错误做法 vs 正确做法（高传播结构）
- **因果链**（链条）：成因→结果→对策
- **辐射式**（中心+分支）：一个概念的多个侧面
- **时间轴**：演变/历史/阶段

用户指定优先；没指定按知识结构自动匹配并说明理由。

**Step 3 图上文案**：标题 ≤12 字带钩子，每模块小标题 ≤8 字 + 一句话 ≤20 字。**先给用户过文案再生成**。按 [`shared/visual-prompts.md`](shared/visual-prompts.md)「图上文字规则」定出字方式：只有标题 + 模块小标题 → 模型直出；带正文句子 → 生图出版式底图，文字走 HTML 排版叠字。**信息图一定有字**，没字的图不叫信息图。

**Step 4 提示词包**：组装结构化提示词（布局描述 + 视觉风格 + 色系 + 模块占位）：
```
[布局框架的视觉描述，如 vertical split comparison layout], 4-6 content modules,
[视觉风格词×3], [主题色系], clean infographic style,
bold title "<标题>" at top, module labels: "<小标题1>", "<小标题2>", ...,
render all text exactly as written, no other text, 3:4
```
（走排版叠字时把文字段换成 `no text`，模块位置留空框）
保存到 `workspace/projects/<slug>/prompt-pack.md`——**提示词包本身就是交付物**（用户可以拿去任何生图工具用）。

**Step 5 生成**：draft 档试布局和风格 → 确认 → final 档正式版：
```bash
$S/toolkit/gen image --prompt "<结构化提示词>" --ratio 3:4 --tier draft
```

**Step 6 交付**：逐字校对后的成品信息图（走叠字的连同 HTML 源）+ 提示词包 + 文案文件 + 结果链接区。

## 执行模式

auto：Step 2 布局自动选并说明理由，Step 5 前确认一次。interactive：每步停。

## 弹性规则

生成失败/效果差 → 提示词包 + 完整文案 + 布局说明照常交付（这已是 80% 的价值），用户可自行在任何工具复现。调研失败 → 基于已有知识做，标注"未联网核验"。

## Gotchas

- **模块贪多**：8 个模块的信息图 = 谁也不看的信息图，砍到 6 以内
- **布局错配**：步骤类知识硬套辐射式 = 逻辑混乱，布局跟着知识结构走
- **无字信息图**：只靠图标传达 = 读者看不懂关系，标题和模块小标题必须上图
- **文字不校对**：模型写的字逐字核对，错一个字就重试或改走排版叠字
- **只有图没有包**：提示词包和文案文件是可复用资产，比一张图值钱

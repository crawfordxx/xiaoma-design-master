# 导演审片标准

审片分两层。第一层是 `review.py` 节奏机检，算得出来的先交给脚本；第二层是导演审片，判断脚本判断不了的：这一镜在剧情里承担什么，给的秒数对不对得起它。

审片人最好没参与创作：只看 storyboard.json、片种卡和机检报告，不听创作理由。没有条件时可以自审，但在 `review.reviewer` 里写明「自审」。

## 1. 审片原则

- **优先级**：情绪 > 故事 > 节奏 > 视线 > 画面构图 > 空间连续（Walter Murch 剪辑六原则）。几条冲突时，从后往前牺牲
- **合适的时长**是能把这一镜要交代的东西完整交代出来的最短时长。拿不准时，叙事片宁长勿短；广告和短视频宁短勿长
- **逐镜判断，不按比例统一削减**：整体要提速时，不能每镜都砍 10%（Reisz）。要找出哪几镜在拖，砍那几镜
- **先机检，后品味**：机检的偏紧和拖沓要先处理掉；处理不了或者是有意为之的，写进 `pace_note`
- **只说症状和改法，不重写**：意见落到镜号，只改被指出的镜头

## 2. 机检怎么算（`review.py`）

所需下限取四项里最大的：

| 项 | 算法 | 依据 |
|---|---|---|
| 看清画面 | 大远景 3、远景 2.5、全景 2、中全景 1.8、中景 1.5、中近景 1.2、近景 1、特写 1、大特写 0.8 秒；快切 0.5 秒 | 景别越远读取越久（Cutting 等对 31,000 个镜头的统计）；0.3–0.5 秒能看清主体；表情识别需要 0.6–0.9 秒 |
| 念完台词 | 字数（汉字、数字按个，英文单词按音节估，全大写缩写按字母）÷ 片种舒适语速 + 换人 0.3 × (说话人数 − 1)。片种语速是「字数 ÷ 镜长」的毛语速，句中气口已经包含在内，不再另加 | 普通话净语速约 5.2 字/秒；影视对白含气口约 3–4 字/秒，口播 4.5–5.5 字/秒；话轮间隙约 0.2–0.5 秒 |
| 读完字幕 | 字数 ÷ 9 + 0.5 秒 | Netflix 简体中文字幕成人上限 9 字/秒，字幕出现后需要识别时间 |
| 动作做完 | 镜头的 `action_s`：画面里的动作做完、界面或信息图看清需要的秒数，由编导或审片人估算 | 动作要做完再切；教程里的操作、信息图要给看清的时间 |

上限：有台词或字幕的镜头是「下限 + 片种余量」；无台词无字幕的镜头是 max(下限 + 余量, 片种停留上限)，有运镜（`movement` 不以「固定」开头）时再加一份余量；快切是下限 + 0.5；标了「停留」的再加 2 秒。换人气口按台词里「名字：」出现的次数减一计，同一人分两行说也算一次换气。

全片级：平均镜长对照片种区间；连续 4 镜有 3 镜同长算匀速；短片种查钩子是否落在要求的秒数内。片种卡里的子类型（一镜到底、竖屏短版、长版）用 `project.asl`、`project.hook` 覆盖片种值。

## 3. 拖沓的信号

1. 台词说完，画面还挂着超过 1 秒，人物没有新反应（对话里约 1 秒的沉默已经是常态上限）
2. 静止的插入镜、特写超过 3 秒，没有新信息，也没有表情变化
3. 动作已经做完，镜头还留着尾巴；或者每个动作都从准备开始拍（该「动作中切入」）
4. 进场太早、离场太晚：寒暄、走进走出、开门关门都保留了
5. 画面、台词、字幕三样在说同一件事
6. 连续几镜在交代同一条信息，可以合并
7. 观众此刻最想知道的答案，拖了很久才给
8. 前 3–5 秒是空镜、logo、铺垫，没有钩子（短片种）
9. 连续多镜时长相近，没有快慢起伏

## 4. 过紧的信号

1. 要交代空间的全景、建立镜头短于 2 秒
2. 台词或旁白念不完，或者只能靠压快语速念完
3. 关键台词、反转、刺激性的话之后没有反应镜头，情绪没地方落
4. 动作还没完成就切走
5. 字幕或字卡停留短于「字数 ÷ 9」
6. 承载表情的镜头短于 1 秒
7. 一镜里塞了太多信息：地点、人物、事件一镜读不完
8. 舒缓的片种（助眠、文旅慢旅行、纪录片）却在密集跳切

## 5. 按剧情功能判断时长

| 这一镜在做什么 | 时长倾向 |
|---|---|
| 钩子、冲击 | 短、狠；广告和短视频前 3 秒内必须给到 |
| 推进剧情 | 2.5–3.5 秒 |
| 交代信息、情绪铺陈 | 4–5 秒；观众每多读一层信息加 2–3 秒 |
| 转折 | 5–7 秒，给观众反应的时间 |
| 升华、余韵 | 6–10 秒 |
| 反应镜 | 刺激性台词后至少 1–2 秒，重场可以 2–3 秒；对话的最后一镜落在主角身上 |
| 动作镜 | 留「起手到顶点」，在顶点切；同一动作拆两镜时各留前 1/3 和后 1/3 |
| 情绪顶点之后 | 不要马上转场，补一两个安静的镜头降温 |
| 重场与过场 | 过场戏快速带过，重场戏才给足时间 |
| 破节奏镜头 | 快片里插一个最慢或景别最大的镜头，往往放在过半处，用来亮产品或主题 |

快慢要成组设计：「4、4、4」秒呆板，「4、4、2」才有节奏；递增或递减的镜长会让情绪累积。

## 6. 审片手法

- **默念计时**：把台词按正常语速念一遍，看秒数够不够、剩多少
- **删一镜试试**：去掉这一镜，故事和情绪少了什么？什么都没少，就是多余
- **找重复**：几镜在交代同一件事，合并
- **问观众此刻最想知道什么**，再看答案在第几秒给出
- **算信息量**：这一镜里的地点、人物、事件读得完吗
- **前后对照**：看前一镜和后一镜，判断这一镜在节奏曲线上该快还是该慢

## 7. 意见格式与结论

每条意见写成：

```json
{"shot": 6, "severity": "P1", "symptom": "旁白 12 字只给 3 秒，念不完",
 "evidence": "机检所需 4.3s；TVC 旁白舒适语速 3.5 字/秒",
 "fix": "延长到 4.5s，从第 9 镜挪 1.5s；或把旁白删到 9 字", "status": "fixed"}
```

- `shot` 是镜号，全片问题写 null
- 严重度：P0 = 观众看不懂、念不完、关键信息丢失；P1 = 明显拖沓或太赶，影响观感；P2 = 可以更好
- 状态：fixed 已修改；wontfix 不改（对应镜头写 `pace_note` 说明）；open 需要用户决定（比如要拆镜、并镜，会让分镜图作废）

审片前先看 `project.assumptions`：写明「用户定稿」的旁白、台词、屏幕文字不提删改意见，只看秒数够不够、画面配不配；确实影响观看的，意见标 wontfix 并注明「用户定稿，建议和用户确认」。

结论：

- **REVISE 退回修改**：有未关闭的 P0，或 3 条以上未关闭的 P1
- **APPROVE_WITH_NOTES 有备注通过**：只剩 P2 或 open 项，或者有已说明的偏差。有 1–2 条未关闭的 P1 时，先按意见改掉再复审被改的镜头；改完只剩 P2 才给这个结论，不要带着 P1 通过
- **APPROVE 通过**：机检通过，审片没有意见

结论写进 storyboard.json 的 `review`：verdict、reviewer、date、summary（一句话总评）、rounds、issues。

## 8. 闭环

1. 跑 `review.py`，先把偏紧和拖沓处理掉（改秒数、删字、标 tempo、给有动作的镜头填 `action_s`、写 pace_note）。`action_s` 要按画面实际估，不要为了过机检凑数
2. 按本文第 3–6 节逐镜审片，写意见
3. 只改被指出的镜头。总时长不变：一镜加了秒数，从拖沓的镜头里挪；节拍时长同步改
4. 改完重跑 `validate.py` 和 `review.py`，只复审改过的镜头
5. 最多 3 轮。第 3 轮还有 P0，就停下来交给用户

出图之前审：改秒数、改台词不用重出分镜图；拆镜、并镜、改画面才需要补图。

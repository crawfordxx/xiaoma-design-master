# 教程 / 操作演示

## 判定信号与相邻片种

- 信号：教程、教学、怎么用、操作步骤、软件演示、X 分钟学会、新手入门、使用说明、跟着做、手工 / 烹饪 / 修图步骤
- 一句话判断：**看完要动手吗？** 观众看完要照着做一遍的，就是教程
- 和**知识科普**的区别：教程交付「会做」，看完能复现一组操作；科普交付「懂」，看完能讲出「因为……所以……」。教程的主角是界面、双手和工具，科普的主角是比喻和图解
- 和**产品宣传片**的区别：产品片挑最好看的瞬间、跳过中间步骤，目的是让人想买；教程每一步都要完整，包括菜单在哪、点哪里、点错了怎么办
- 和 **MG 动画**的区别：MG 把流程画成图标和箭头，讲「流程是什么」；教程拍真实界面和真实的手，讲「具体怎么点」
- 和**达人口播**的区别：「三个小技巧」如果每个技巧都给完整步骤、不带货，是教程；重点在种草和人设、结尾挂链接，是口播

## 默认规格

| 项 | 速学版（30–90s） | 标准版（3–5min） | 课程版（5–15min） |
|---|---|---|---|
| 镜数 | 8–18 | 每分钟 8–12 | 每分钟 6–10 |
| 平均镜长 | 3–5s | 5–8s | 6–10s |
| 画幅 | 9:16（抖音、视频号） | 16:9（B 站、课程平台） | 16:9 |
| 内容量 | 1 个技巧，3–5 步 | 1 个功能，3–6 个大步骤 | 一个完整任务，分章节 |
| 旁白语速（说话时） | 4.5–5 字/s | 4.5–5 字/s | 4–4.5 字/s |

全片平均：录屏类 4–4.5 字/s，旁白几乎不停；实拍手作 3–3.5 字/s，等火候、等结果时停嘴 3–8 秒。不要为了「填满」往里塞话。

## 结构模板

标准版（5 分钟）按「先终点、再路线」排节拍：

| 节拍 | 占比 | 做什么 |
|---|---|---|
| 成品预览 | ~5%（前 10–20s） | 先给做好的样子，最好是「之前 → 之后」一次切换，再说一句它省了什么事 |
| 准备 | ~6% | 版本、工具、素材，以及「你的数据 / 材料要长这样」；最常见的前置错误在这里排掉 |
| 步骤演示 | ~59% | 按编号走，每步一个动作 + 一个结果；每 30–45 秒一个步骤卡 |
| 易错点 | ~12% | 演一次错的结果，再演怎么改回来 |
| 举一反三 | ~10% | 同样的方法换一个场景用一次，或给一个进阶用法 |
| 回顾 | ~8%（短片可到 13%） | 黑底编号清单 3–5 条一屏收齐，旁白逐条念，每条 4–6 秒；交代练习素材或下一集 |

全片超过 3 分钟时，默认先做开头 60–90 秒：成品预览 + 准备 + 前 1–2 个步骤。这一段决定观众会不会跟到最后。

单集超过 6 分钟就按子目标分章，每章开头上大字标题：观众看教程平均只看 2–3 分钟，常跳着看、回看。

其他常用结构：
- **单技巧速学**：痛点一句 → 成品 → 三步 → 成品再看一遍，适合竖屏
- **前后改造**：乱的原样 → 一步步改 → 改完左右对比，适合排版、修图、收纳
- **跟做实拍**：手工、烹饪、健身，主机位不断，关键手法切特写，用量、温度、次数上屏
- **问题排查**：报错现象 → 原因 → 修复 → 验证修好了，适合软件和设备故障

## 一步一镜：操作可复现

教程只有一个标准：观众能照着做出来。写每一镜之前先问：观众暂停在这一帧，知道手该放在哪吗？

1. **先结果后步骤**：开头 10–20 秒内让观众看到成品。看不到终点的人，不会跟着走完二十个步骤。烹饪、手作的封面和标题已经是成品时，可以直接开做：第一镜交代主料和用量，成品特写放在结尾，停 ≥5 秒
2. **一步 = 一个动作 + 一个结果**：「点哪里」和「点完变成什么」都要拍到。只有动作没有结果，观众不敢确定自己做对了
3. **说清三件事**：位置（菜单在顶部、按钮在右下角）、动作（单击、双击、右键、按住拖动）、参数（选哪项、填什么）。位置和动作进旁白，参数写成屏幕字，光标和高亮框同时指过去
4. **默认整窗，看不清才放大**：横屏长教程整窗录屏，一个技巧一镜到底；只在看不清时放大（具体点击、刚输入的文字、小字参数），放大完回全屏。连续放大超过两镜，观众就不知道自己在界面的哪儿了。竖屏把操作区裁成竖条
5. **不跳步**：等待可以加速（加载、烘烤），角落标「×4」或计时；但不能剪掉任何一次点击
6. **易错点演出来**：拖错一个字段、出来一堆乱数，再撤销重来，比旁白说「注意别拖错」管用得多
7. **一步配一句目的**：每 1–2 步配一句「加 X 的目的是……」，在操作镜上直接说，不另开讲解镜

| ❌ 看了也做不出来 | ✅ 能照着做 |
|---|---|
| 旁白「然后插入透视表」，画面直接跳到建好的表 | 光标移到顶部「插入」→ 放大点「数据透视表」→ 对话框弹出，范围栏已填好 → 点确定 → 右侧出现字段面板 |
| 「把字段拖进去」 | 「把『地区』拖到『行』」：放大字段面板，光标按住「地区」拖到「行」松开，左边同步长出一列地区名 |
| 等加载时画面卡住 8 秒 | 加速 4 倍，角落标「×4」，旁白趁这几秒预告下一步 |
| 讲师占满画面讲两分钟原理 | 讲师一句话说为什么，马上切回界面动手 |

录屏也要写景别，按界面范围来定：整个窗口 = 全景，一个面板或对话框 = 中景，一排菜单或几个格子 = 近景，一个按钮 = 特写。录屏的「推」「拉」就是放大和缩回。

## 节奏基准

- 成品预览 2–3 镜，每镜 3–6s，快速给结果
- 操作镜 4–8s，以光标走完、点击、结果出现为准；结果出现后停 0.5–1s 再切
- 一步约 6–8 秒，按「步数 × 7 秒」估正片时长，偏差超过三成就是漏步或拖沓
- 一步几镜看拍法：实拍手作 2–3 镜一步；固定机位一步一段同机位跳剪；录屏一个技巧一镜到底，分镜里仍按子步骤拆镜写秒数，标「同一录屏连续」
- 镜长分档：实拍快剪 2–2.5s；实拍固定机位约 5s；录屏一个技巧一镜 30–45s
- 步骤卡 1–1.5s，或叠在该步第一镜的顶部；每 30–45 秒出现一次，告诉观众「我跟到哪了」
- 讲师露脸不超过全片 10–20%，放在开场建立信任、步骤之间换气、提醒易错点；实拍手作里手部就是主体，可占 80% 以上；录屏的讲师小窗可以常驻，但不挡操作区
- 5 分钟教程出彩镜头 3–5 个：成品揭示、错误示范、前后对比、首尾同一张成品

## 招牌镜头

- **成品先行**：同一窗口里乱的原样一下变成做好的样子，擦除或叠化
- **全屏定位**：完整界面，光标从中间出发，高亮框框出接下来要动的区域
- **局部放大**：缓推到按钮或对话框，橙色高亮框 + 点击涟漪
- **手部俯拍**：顶拍键盘鼠标或工作台，交代快捷键、按住不放、手法力度
- **固定双机位**：备料用正俯拍案板，切好的料碗留在画面边缘越摆越多；制作换高位 45° 灶台机位，同机位跳剪压缩等待，只在状态变化点插 2–3 个锅内特写
- **中景特写交替**：腰部平视中景（画面上缘切在下巴，不露脸）交代动作，切 45° 手部特写看手法，再切回中景；镜长 2 秒左右
- **步骤卡**：「第 2 步 · 拖字段」，编号贯穿全片
- **错误示范**：红框标出错误结果，撤销，再做对
- **前后对比**：左右分屏或擦除，同一区域只差一处
- **讲师入画**：半身对镜，一句话说清「这一步为什么要做」

## 扩展列

- `操作步骤`：写成「步骤号 · 动作 · 对象」。例：「1-2 · 单击 · 菜单栏『插入』→『数据透视表』」「—（成品预览，无操作）」。剪辑和录屏的人照这一列核对有没有漏步
- `屏幕内容`：写清屏幕此刻的状态、放大到哪、标了什么。例：「中景 · 对话框居中 · 绿框框住范围栏『A1:F201』」「实拍手部 · 无界面」。录屏的人照这一列准备数据和界面状态

## 画风

默认 `ui-screen`；手工、烹饪、健身这类实拍教程用 `realistic-studio`（台面俯拍）或 `documentary-natural`（家里实拍）。

`prompt_prefix` 参考：电脑软件教程视频画面，清晰的扁平化通用软件界面，界面文字清楚可读，带鼠标指针和高亮框标注；实拍部分是明亮干净的书桌与讲师双手，柔和白光

- `allow_text: true`。图里的字只写一两处关键的（菜单名、按钮名、范围），加引号；其余写「模糊示意的数据」
- 不画任何真实软件的 logo 和界面，写「通用表格软件」「虚构界面」，真实录屏阶段再换素材
- 界面建一条 `refs`（type: location），写清菜单栏、强调色、表格网格，每个录屏镜头都挂上，全片才像同一个软件
- 录屏和实拍混剪时，前缀要同时兼容两种画面；讲师的手或讲师本人跨镜出现就建角色 `refs`，写清袖口、手表这类认手的细节
- 高亮框颜色全片固定含义：比如橙色 = 下一步要点这里，绿色 = 检查这里对不对，红色只给错误示范

## 声音

- 旁白为主，说话时 4.5–5 字/s；菜单名、快捷键放慢重读，前后留半拍
- 旁白和光标同步：说「插入」时光标正好落在「插入」上，旁白不领先画面超过半句
- 单击、键盘、拖放配轻音效，让观众「听见」操作发生；步骤卡用全片统一的一个提示音
- BGM 轻、无人声，音量压在旁白下面，步骤卡处可以抬一下
- 旁白人称用「你」：「你会看到右边多了一个面板」，不说「我们可以看到」

## 常见坑

- 前 30 秒讲背景和原理，观众还没看到成品就划走了
- 跳步：旁白说「然后」，界面已经到了下一个状态
- 光标乱晃、画面一直推拉，观众找不到焦点
- 一直放大不回全屏，观众不知道按钮在界面的哪个角
- 字太小：16:9 录屏缩到手机上，菜单字看不清；关键操作一定要放大
- 用了观众手里没有的版本、插件、素材，开头没交代
- 示例数据带真实客户、员工信息，没有脱敏
- 讲师小窗一直压在界面右下角，正好挡住要点的按钮

## 变体

- **竖屏速学（30–60s）**：第一句说痛点，3 秒内上成品，在 `project.hook` 里写 3；界面放大裁成竖屏，字幕通栏，每步一镜。也可以前 15–18 秒用 1–2.5 秒的反应镜演一段情景（被派活 →「搞定了」），再进录屏
- **实拍手作 / 烹饪**：顶拍做主机位，侧面 45° 补手法；用量、温度、时间写成屏幕字；等待段用延时
- **硬件 / 产品使用说明**：产品特写 + 手部操作 + 指示灯或屏幕状态特写；安全提示单独一镜，不藏在旁白里
- **系列课程**：片头统一、5 秒以内；每集开头用 10 秒回顾上集成品，结尾预告下一集要做的东西。第一集也可以先上本集要点卡（「1. 从哪开始 2. 用什么软件」）和整套路线图

写分镜前挑一部最接近的范本，照它的排法走。实测镜长和来源见 `references/benchmarks.md`。

## 节奏审核参数

`review.py` 按下面的参数做节奏机检，规则见 `references/director-review.md`。项目属于本卡里的某个子类型（例如竖屏短版、一镜到底、长版）时，在 `project.asl`、`project.hook` 里写那个子类型的平均镜长区间和钩子时限。

```pace
asl = 2.5-10
cps = 4.5
slack = 1.5
hold = 8
hook = 0
```

asl 平均镜长区间（秒）· cps 台词旁白舒适语速（字/秒）· slack 有台词镜头的余量（秒）· hold 无台词镜头的停留上限（秒）· hook 钩子最晚结束（秒，0 表示不查）

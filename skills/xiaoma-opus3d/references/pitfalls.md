# 踩过的坑（乌镇实战记录）

每一条都是真的发生过、花时间排查过的。按出现的阶段排列。

## 环境

- **无头 Chromium 默认没有 WebGL2。** macOS 上要加 `--use-angle=metal`（`scripts/browser.mjs` 已经加了），否则要么拿不到上下文，要么掉到软件渲染、慢几十倍。Linux 上换成 `--use-angle=vulkan` 或 `--use-gl=egl`，先用一个只读 `UNMASKED_RENDERER_WEBGL` 的小脚本确认拿到的是真 GPU。
- **`npm i esbuild` 可能卡在安装后的收尾步骤**（它要校验或下载平台二进制）。先停掉，看 `node_modules/esbuild` 和 `node_modules/@esbuild/<平台>` 在不在，`node -e "import('esbuild').then(e=>console.log(e.version))"` 能打出版本号就说明已经能用。
- **Playwright 版本和本机 Chromium 版本可能对不上。** `browser.mjs` 会自动找 `~/Library/Caches/ms-playwright` 里最新的 chromium，找不到时用环境变量 `CHROME` 指定。

## 平面图

- **检查脚本一定要写。** 乌镇第一次跑 check-layout 就抓出 3 个真问题：商铺压到小路、晒布场被当成实心块导致园内的树报重叠。肉眼看平面图看不出来。
- **区块内部的空地会在航拍里露馅。** 平面图上的“后排空地”要登记成填充区，交给某个区块用低精度建筑群填满。
- **桥、台阶这类东西两端的落地空间要留够。** 平桥两端只比岸线多 1m，踏步放不下，桥的 Agent 只好把桥台伸进水里。layout 里给桥留的长度要按“桥面高 ÷ 0.43（踏步坡度）”算。

## 公共件

- **大量同类物件必须先写参数化生成器。** 寺庙是几栋各不相同的建筑；古镇是几十栋相似的民居。两岸交给两个 Agent，如果各写各的，两岸就是两种风格。派活前由主 Agent 写好 `shared.js`（乌镇是 house.js），子 Agent 只调用。
- **生成器要先单独测一遍再派活。** 截一张近景、一张远景，看瓦垄密度、窗格、比例。4 个 Agent 依赖它，它有 bug 就是 4 份返工。
- **UV 统一用米。** 不然同一张砖纹贴在 1m 的台阶和 10m 的墙上密度不一样。`geom.boxM / planeM` 已经按米缩放。
- **`mergeByMaterial` 会丢掉顶点色和自定义属性。** 需要它们的区块直接用 `mergeGeometries`。
- **亮窗不能用整张室内贴图。** 室内贴图 3m 一个循环、大部分是暗底，1m 宽的窗经常正好落在暗处，于是一扇都不亮。小窗用均匀发光材质，大的敞开店面才用带货架剪影的贴图。

## 光照与后期

- **低太阳角下物理天空（Preetham `Sky`）会整片过曝发白**，而且亮度随太阳高度剧烈变化，很难调。改用自写的渐变天空（`assets/template/src/sky.js`），颜色在两个关键时刻之间插值，完全可控。
- **NaN + bloom = 整帧全黑。** 只要一个像素是 NaN，bloom 的模糊会把它扩散到整个画面。乌镇遇到过两次：天空 shader 里 `pow(负数)`（浮点误差让 `dot*0.5+0.5` 略小于 0），水面 shader 在某些机位下也出过。对策两层：
  1. shader 里所有 `pow` 的底数、`sqrt` 的参数、`normalize` 的向量都夹紧或判零。
  2. 后期链在 bloom 之前加一道 NaN 清零 pass（`main.js` 已经加了），坏像素最多黑一个点。
  3. **判断 NaN 要用位模式**：`(floatBitsToUint(x) & 0x7f800000u) == 0x7f800000u`。Metal 的快速数学会把 `isnan(x)` 和 `x != x` 直接优化成 false，看起来加了保护其实没生效。
  4. 写一个回归脚本：随机几百个机位（贴水面、高空、正对/背对太阳）× 随机 t，检查中心和四角有没有纯黑。乌镇的水面就是这样抓出第二处 NaN 的。
- **EffectComposer 的离屏渲染目标不吃 `antialias: true`。** 必须给它传 `samples: 4` 的 HalfFloat 渲染目标，否则成片没有抗锯齿，细柳条、竹竿会闪。
- **俯视对位图要关雾、提曝光。** 正交相机放在 150m 高空，雾会把整个场景吃成一片底色；黄昏光线下屋顶也是黑的。`main.js` 对正交机位自动关雾、曝光 ×2.5。
- **ACES 会把高亮的饱和红洗成黄白色。** 红灯笼的发光强度上限控制在 1.7 左右，发光色用偏深的红（0xff2a10），靠 bloom 出光晕。
- **太阳只有几度高时，几乎所有贴地的地方都在长阴影里**（7m 的房子投 100m 的影子）。暗部只靠天光，天光强度要比“常识值”高（乌镇用到 1.25 → 0.9），否则水边近景一片死黑。
- **环境贴图（PMREM）每帧重建太贵。** 按 t 量化（每 0.5 秒一次），既省时间又保持确定性。

## 子 Agent 协作

- **给每个 Agent 一个临时背景区块**（`_ground`、`_water`），它们就不用等别人做完才能截图。
- **跨区块的衔接问题会在施工中冒出来**（压顶石缺口要桥台填、河埠头处美人靠要断开、水面要有透明度才能看到水下石阶）。Agent 只能报告不能改别人的文件，所以主 Agent 要及时转达给相关的 Agent。
- **公共件发现 bug 时，让 Agent 报告、主 Agent 改。** 改完要通知正在用它的 Agent，并说明“不要在自己的文件里补偿”，否则会出现两边都调、调过头。
- **Agent 写的特写坐标要它在 review 里给出来**（世界坐标 + 推荐机位），排镜头时直接用，不用重新找。

## 镜头（导出视频时）

- **接触表（每个镜头取 4 帧拼一张）在出片前能抓出大部分问题**：黑帧、穿墙、背光、构图切字。
- **拉远用指数距离**，否则 0.3m 拉到 100m 的过程里，前 10% 的时间就已经离开特写物件 10m，特写形同虚设。
- **焦点不能比相机先走。** 焦点一旦移向远景目标，而相机离物件还只有几米，`相机 = 焦点 + 方向 × 距离` 就会把相机带进墙里。用 `focusEase` 让焦点晚点动。
- **起幅和落幅的相机方向别相反。** 方向插值会从中间绕过去，扫进旁边的房子。起幅机位放在物件的“远景同侧”。
- **逆光要看背景是什么。** 柳叶背后是房子就不是逆光。选背后视野开阔、正对太阳方位的物件。
- **傍晚背光面的特写是黑的。** 选朝太阳那一侧的物件拍（乌镇的河埠头从朝北的 ws3 换成朝西的 ws6）。
- **起幅看清全部要读的字**（酒旗第一次构图把“三”字顶切掉了）。

## 实时与嵌入

- **高像素比屏幕上画布会撑出容器。** `renderer.setSize(w, h, false)` 不设 CSS 尺寸，像素比为 2 时画布按物理像素（2 倍）显示，只看得到左上四分之一。无头浏览器默认像素比是 1，测不出来；`test-viewer.mjs` 专门在像素比 2 下测。
- **动态 `import(\`./zones/${z}.js\`)` 打包不进单文件。** 区块要在 `zones/index.js` 里静态 import。
- **单文件要能双击打开（file://）**：脚本必须内联成普通 `<script>`，不能用 ES 模块引用外部文件（file:// 下跨文件模块加载会被拦）。内联时把 `</script` 转义成 `<\/script`。
- **区块在 build 时读画面尺寸的东西（反射贴图）**，窗口一变就失配。`scene.js` 在 `setSize` 时统一调整所有 Reflector 的渲染目标；区块要用 Reflector 而不是自己建离屏渲染目标，否则主 Agent 管不到。
- **光照时刻和动画时刻要分开。** 交互模型里光照固定在最好看的那一刻，船、布、水波照常跟着真实时间动。`render({ lightT, animT })`。
- **反射是最贵的一项**（等于整个场景再画一遍）。低档关掉反射：`scene.js` 会跳过 Reflector 的渲染，并把材质的 `uReflect` 置 0，所以反射 shader 要支持 `uReflect = 0` 时退回本色。
- **`touch-action: none`** 要设在画布上，否则手机上拖动会变成滚动页面。
- **自动降档只降不升**，否则在临界帧率上会来回跳。切回标签页时那一帧的大间隔不算。
- **看不见时停渲染**：嵌在长页面里滚出屏幕、标签页切到后台时，`IntersectionObserver` + `document.hidden` 停掉渲染，省电。
- **开发机帧率不代表普通设备。** M 系列 Mac 上三档都是 120fps，测不出差别。要求手机流畅时，守住 BRIEF 的预算（乌镇全场景约 700 万三角形、500 个 draw call，在中端设备上会很吃力；手机目标建议 150 万三角形、200 个 draw call 以内）。
- **GitHub README 不能嵌交互模型。** JS、iframe、WebGL 都会被过滤。交互模型放 GitHub Pages，README 里放预览动图（链接到在线版）和漫游视频。动图控制在 5MB 以内（乌镇：560px 宽、10fps、96 色，4.8MB）；视频要注意两点：README 里的 `<video>` 标签和仓库里的 mp4 链接都不会出播放器，只有网页上传的视频附件（`github.com/user-attachments/assets/…`，单独一行）可以；免费账号的视频附件上限 10MB，超了只会显示“Failed to upload”。乌镇 70 秒：附件版 540p、crf 28、7.5MB；仓库里的清晰版 720p、crf 27、14MB（仓库单文件上限 100MB）。
- **初始视角决定第一印象。** 高位斜视、顺着光线方向，让剪影、亮灯和地标同时入画。

## 导出视频（可选）

- **不要实时录屏。** 场景写成 `renderFrame(t)` 纯函数，逐帧截图再用 ffmpeg 合成。
- **`render.mjs --verify` 必须过。** 同一个 t 在两个独立页面里渲染，md5 要一致；先渲染别的 t 再回来渲染，结果也要一致（排除累积状态）。
- **乌镇的实测速度**：1080p、带反射和 bloom、约 700 万三角形，M5 Pro 上每帧约 220ms（2 个并行页面），70 秒 2100 帧约 8 分钟。
- **字体依赖本机。** Canvas 写字用的是系统字体（Songti SC、楷体会回落成其他字体），换机器出片字形可能变。要求一致时，就在同一台机器上出片。

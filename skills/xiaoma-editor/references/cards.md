# 字幕与字卡

> 一句话：**画面里的字一律不让视频模型画，全部后期贴。** 模型画出来的字是乱码，
> 钟面会停在 10:10，手机屏会长出不存在的品牌。

对应脚本：`scripts/cards.py`（解析 + 排版成透明 PNG）、`scripts/assemble.py` 的 `build_overlays`（贴到时间线上）。

---

## 1. 上游必须遵守的三条（写给分镜 / 出片技能）

1. `frame_prompt` / `visual` 里**一律不出字**：手机屏写「屏幕纯白发光、无任何字」，
   门牌写「门牌空白」，钟表写「表盘无指针」，账本 / 诏书 / 单据写「纸面空白无字」
2. 要贴什么字，全部写进该镜的 `on_screen_text`，**制作备注写在括号里**：
   `"周野 · 夜班司机（竖排名牌，画右，后期合成）"`。括号里的内容只用来判类型，绝不上屏
3. 屏幕类字卡（手机屏、监控、电视、HUD）在 shot 上给 `screen_box = [x, y, w, h]`
   （相对**片段原画面**的 0–1 比例）。给了就把字贴进屏幕区域；没给就退到画面中部信息框

「字卡不叠」也是上游的事：片名单独一卡、时间地点另一卡、「AI 生成 · 纯属虚构」只做角标，
三者不要压在同一镜。真压在同一镜了，本技能会把它们**排成序列依次出现**（见第 3 节），
但那是补救，不是设计。

## 2. 五种卡类型

| 类型 | 触发（括号里的备注含） | 排版 |
|---|---|---|
| `name` | 名牌 / 人名条 | **竖排**，34 号，画右（距右边 6% 画宽），纵向 18% 画高处；`·` 或 `|` 后面是身份，另出一块 20 号带底框的横排小标签贴在竖排下方 8 px |
| `screen` | 屏幕 / 手机 / 界面 / 屏 | 有 `screen_box` → 贴进该区域；没有 → 画面中部信息框（30 号，宽 ≤60% 画宽，纵向中心 42%，底框 `rgba(12,14,18,200)`） |
| `title` | 片名 / 字卡 / 标题 / 时间卡 / 地点卡 | 46 号，无底框（黑描边），宽 ≤80% 画宽，画面正中 |
| `time` | 内容本身像时间且 ≤16 字 | 26 号带底框，宽 ≤50% 画宽，左上角（5% 画宽，7% 画高） |
| `caption` | 以上都不是（心声、旁白字幕等） | 30 号带底框，宽 ≤86% 画宽，顶部 8% 画高处 |

`time` 的判定正则：`\d:\d` 形式的钟点、`N年/月/日/号/点/时`、凌晨 / 清晨 / 深夜 / 傍晚 / 午夜、
结尾的「前 / 后」、「N 天/小时/分钟/年 前后」。**并且长度 ≤16 字**——
「2019年那个下着雨的深夜十一点整，一切都变了」虽然含时间词，但是一句话，按 `title` 排。

对白字幕（不是字卡）：34 号，无底框，黑描边 `stroke_width = max(2, 字号/12)`，
宽 ≤86% 画宽，底部留 7% 画高。

角标（虚构声明）：18 号带底框，右上角内缩 12 px，从第 1 镜一直挂到画面结束。
`assemble.py --label ""` 可以关掉。

## 3. 解析规则（`parse_ost`）

输入是 `on_screen_text` 原始字符串，输出是「要上屏的卡」+「被丢掉的内容」（后者会进剪辑报告的字卡审计）。

按顺序做四件事：

1. **抽括号**：`（…）` 和 `(…)` 里的全部内容抽出来，记为「备注」，**不上屏**。
   备注只用来判类型（第 2 节的关键字表）
2. **按 `／` 或 ` / ` 切分**剩余内容，得到多张卡
3. **剔除虚构声明**：任何一段命中「虚构 / 纯属 / 演绎 / AI 生成 / 人工智能生成」→ 丢掉，
   记为「声明并入角标」。声明只做角标，不做卡
4. **屏幕状态序列**：`screen` 类型再按 `→` / `->` / `⇒` 切一次
   （`"11:39 → 11:40（屏幕合成）"` → 两张卡，先 11:39 后 11:40）

一段都没剩下时返回空列表（比如 `on_screen_text` 只写了一句虚构声明）。

### 序列编号：同一镜多张卡不叠

`_sequence` 把 n 张卡平均分到这一镜的时长里：第 i 张卡的出现区间是
`[i/n, (i+1)/n]`（相对镜头的比例），`build_overlays` 换算成成片绝对时间
`t0 + start × dur` 到 `t0 + end × dur`。

所以 `"深夜11:40 ／ 夜班车 ／ 虚构演绎（时间字卡 + 片名 + 片名下小字）"` 在一个 2.4 秒的镜头里会变成：

| 时间 | 内容 | 类型 |
|---|---|---|
| 0.0–1.2 s | 深夜11:40 | time（左上角小框） |
| 1.2–2.4 s | 夜班车 | title（画面正中） |
| 全程角标 | AI 生成 · 纯属虚构 | 角标（「虚构演绎」被并进这里） |

### 台词 → 字幕（`line_text`）

`dialogue` 和 `vo` 字段的原文要先剥壳：

- 去掉说话人：开头 ≤12 个非标点字符 + 冒号（`周野：` / `老陈（背过身）：`）
- 去掉括号里的表演提示
- 去掉成对的引号 `"" “” 「」`

字幕的显示区间：这一镜量到了人声 → 从人声起点前 0.15 秒到人声结束后 0.4 秒；
没量到 → 整镜。**字幕跟着声音走，不跟着镜头走**，否则会出现「字幕已经换下一句了，声音还在念上一句」。

## 4. 屏幕区域换算（`map_screen_box`）

`screen_box` 是相对**片段原画面**的比例，输出画面是「等比放大到填满 + 居中裁切」，所以要反向换算：

```
s  = max(W / src_w, H / src_h)              # 放大倍数
ox = (src_w × s − W) / 2                     # 横向被裁掉的总量的一半
oy = (src_h × s − H) / 2
x  = box[0] × src_w × s − ox
y  = box[1] × src_h × s − oy
w  = box[2] × src_w × s
h  = box[3] × src_h × s
```

然后夹到画面内。夹完宽或高小于 8 px 就返回 `None`（区域太小，贴不进去，退回中部信息框）。

`src_w / src_h` 来自素材探测，不是输出尺寸——横构图素材投竖屏画幅时这一步差得很远。
例：16:9 的 1280×720 素材 → 720×1280 输出，`s = 1.778`，横向裁掉 1556 px，
`screen_box = [0.4, 0.4, 0.2, 0.2]` 落到输出画面的 `(132, 512, 455, 256)`。

### 贴进屏幕区域时的处理（`screen_png`）

不是简单地把字放上去，而是：

1. 先铺一层**不透明度 235/255 的亮屏底色** `rgb(238,242,245)`，圆角 `max(4, 宽/16)`
   ——这一层的作用是**盖住模型可能画出来的乱码**。只做透明底 + 深色字，乱码会透出来
2. 字用深色 `rgb(25,28,32)`，像真的屏幕显示
3. 字号自动缩放：从 `区域高 / k × 0.5` 起，每次 ×0.9，直到折行后总高 ≤ 区域高的 86%
   且每行宽 ≤ 区域宽的 86%

## 5. 排版基准与折行

`Typesetter(font_path, W, H)`，`k = min(W, H) / 720`。所有字号都写在「短边 720」基准上，
乘以 `k` 得到实际像素——720×1280 时 34 号就是 34 px，1080×1920 时就是 51 px，
**不用为每个分辨率重写常量**。字体最小 10 px（`max(10, int(size × k))`）。

折行按字符逐个量宽（`font.getlength`），超过 `max_w` 就断行；`\n` 是硬断行。
行高 `1.35 × 字号`，内边距 `0.5 × 字号`，每行水平居中。
带底框的用圆角矩形 `rgba(0,0,0,150)`（可覆盖），不带底框的用黑描边。

## 6. 为什么用 PIL 而不是 drawtext / libass

| | `drawtext` | `libass`（ASS 字幕） | PIL → PNG overlay（本技能） |
|---|---|---|---|
| 中文逐字折行 | ❌ 不支持，长句直接溢出画面 | ⚠️ 靠 `\N` 手动断，不会自己按宽度折 | ✅ 按像素宽度逐字量 |
| 竖排（名牌） | ❌ | ⚠️ 要 `\frz` 逐字旋转拼 | ✅ 直接逐字画 |
| 不透明底板盖住屏幕乱码 | ❌ 只能画矩形 box，不能圆角、不能盖住再写字 | ⚠️ 能做但样式表难写 | ✅ 就是一张图 |
| 字号随区域自动缩放 | ❌ | ❌ | ✅ 循环缩到装得下 |
| 屏幕区域按比例换算 + 裁切补偿 | ❌ 要自己算表达式 | ❌ | ✅ 一个纯函数，可单元测试 |
| 字体路径转义 | ❌ 地狱（冒号、空格、反斜杠都要转义，跨平台不一致） | ⚠️ | ✅ 传文件对象 |
| 依赖 | ffmpeg 编译时要带 freetype，各机器不一样 | 要带 libass | pip 装 Pillow，可控 |
| 能否肉眼中途检查 | ❌ 要渲染视频才知道 | ❌ | ✅ PNG 是中间产物，直接打开看 |

最后一条最实用：每张卡先落成 `edit/<成片名>/png/ostNN_*.png`，
再连同 `sheet.jpg`（每镜中间帧拼图）一起目检。**能在图片上发现的问题，不要等到视频里发现。**

代价：每张卡一个 PNG + 一条 `overlay` 滤镜，卡多了滤镜图会很长
（32 镜约 30 张图，渲染几分钟）。这个量级完全能接受；真到几百张再考虑分层渲染。

## 7. 字体

`find_font(override)` 的查找顺序：

1. 命令行 `--font`
2. 环境变量 `XIAOMA_FONT`
3. macOS 系统中文黑体 / 苹方 / 冬青黑 / Arial Unicode
4. Linux 的 Noto CJK（几个常见发行版路径）/ 文泉驿微米黑、正黑 / Droid Sans Fallback
5. `fc-list :lang=zh file` 的第一个

`--font` 或 `XIAOMA_FONT` 指了不存在的文件 → 直接报错（不静默退回默认字体，
否则你会拿到一个和预览不一样的成片）。全都找不到 → 报错并给出安装建议
（macOS 自带；Linux 装 `fonts-noto-cjk` 或 `fonts-wqy-microhei`）。

## 8. 常见翻车

| 症状 | 原因 | 修 |
|---|---|---|
| 画面上出现「后期合成」「画右」这类字 | 备注没写进括号 | 括号包起来，`parse_ost` 会自动丢 |
| 时间、片名、声明三行叠在一起 | 写进了同一镜的同一个 `／` 分段 | 用 `／` 分开，会自动排成序列依次出现 |
| 虚构声明做成了一张大卡 | 声明混在正文里 | 声明命中关键词就自动剔除，只保留角标；要关角标用 `--label ""` |
| 屏幕上的字浮在画面外 | 没给 `screen_box` | 给 `screen_box`；给不了就接受中部信息框，别指望它对准屏幕 |
| 屏幕区域贴歪了 | `screen_box` 按输出画幅写的，不是按素材原画幅 | 按**素材原画面**的 0–1 比例写 |
| 屏幕里透出乱码 | 只贴了字没铺底色 | `screen_png` 已经铺 235/255 的亮屏底；还是透说明素材屏幕太亮，重出该镜（提示词写「屏幕纯白发光、无任何字」） |
| 字幕比声音早 / 晚 | 字幕按整镜显示 | 装转写库，字幕会跟着人声区间走 |
| 名牌竖排挤成一行 | 字体不支持竖排？不是——是 `·` 分隔符没写 | 用 `名字 · 身份`，`·` 后面才会拆成横排小标签 |
| 字太小 / 太大 | 换了分辨率没换字号 | 不用换，字号按短边 720 等比缩放 |
